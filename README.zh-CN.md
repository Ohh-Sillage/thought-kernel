## 先说一句可能不中听的话

这份东西**不会让你的回答质量变高**。我们测过：在最严格的盲评里，装上它，回答反而变差 1.39 分（9 题里 7 题两位评委都判更差）。

那为什么还开源？

因为**「回答变差」和「东西没用」不是一回事**。真正的问题从来不是「模型不够聪明」，而是三件更具体的事：

1. 该用某个思考框架的时候，你想不起来；
2. 想起来了，每次还得手写一大段角色设定和流程约束；
3. 同一个框架，做重大决策和改个错别字，用的力气是一样的。

这三件事**不需要模型变强就能解决**。解决它们的代价是「回答形状变了」——更全、假设更显式、更知道边界在哪。这在评分表上加不了几分，但在真实交付里省掉的是「返工」。

我们把这个取舍原样写进了 README，而不是藏起来。往下看实测那一节。

## 三条原则（会过期的部分是思想，不是原则）

25 项思想是可以被穷举、被替换、被淘汰的。下面三条不能——它们换到 agent 编排、RAG 流水线、工作流引擎上同样成立。

**一、先判该不该做，再谈怎么做。**
不做也是一种正确输出。绝大多数提示词增强工具死在这一条上：它对每一句话都做点什么。这里的做法是先过一道**落差测试**——给出最简正确回应之后，用户还会不会追问「为什么／怎么做／选哪个／还有别的吗」？不会，就直接答，不套框架、不加「顺便提醒你」。

**二、删得掉的才叫架构。**
三层：主干 → 场景包 → 画像。删掉任意一个场景包，主干仍能落到兜底，不报错、不崩。场景之间只用「不适用信号」互相划界，不能靠排序抢——排序会让人为了「塞进去」而扭曲判据。

**三、注入约束，不改写内容。**
三种注入形态：`wrap` 改的是提示词周围的约束，`inject` 静默地只影响推理结构，`interactive` 把它变成一段对话。三者都不替换用户真正问的那件事。**用户原意是不变量，变的只是压力大小。**

> 由第一条派生出第四条：**力度跟着代价走**。不可逆决策给满压力，随口一问给一句话。

## 三十秒装上

**一、Claude Code / WorkBuddy 一类**

```bash
git clone https://github.com/<你的账号>/thought-kernel.git
cp -r thought-kernel/skill ~/.claude/skills/thought-kernel
```

然后直接说人话：

```
用费曼学习法陪我学 Transformer 的位置编码
帮我做个项目计划，先别急着给方案
这个 offer 要不要接，给我正反论证
以后都用效率优先
```

**二、Cursor / Windsurf 一类**：把 `prompt/KERNEL.md` 整个拷进规则文件。它是自包含的，没有相对链接。

**三、什么都不装**：打开 [`demo/index.html`](demo/index.html)，或者把 `prompt/KERNEL.md` 当系统提示词粘贴。

逐宿主的细节与坑见 [`GETTING_STARTED.md`](GETTING_STARTED.md)。

## 我们实测了什么（包括怎么输的）

**设计**：9 道真实提问（写作／编码／调试各 3，取自真实会话日志）× 2 臂（裸模型 / 加 skill）× 2 位独立评委盲评。同一题的两份回答打乱成 U01/U02，评委不知道哪份来自哪一臂。满分 20，噪声带 ±0.67，只有 |Δ| > 1.34 才算真差异。

| 评委 | Δ（装 skill − 裸模型） |
|---|---|
| A | −1.33 |
| B | −1.44 |
| **均值** | **−1.39** |

**9 题里 7 题，两位评委都判它更差。**

**为什么——不看分数，读原文：**

- **「不许编造」被执行成了「交一张空表」**：让按招聘要求填简历项目，裸模型直接给了成稿（编了两个数字，被抓出来扣了分）；加 skill 的那份给了**占位符骨架**，还教用户怎么填。编造没了，可用性掉得更多。
- **交付契约套到小故障上，成了负担**：「Win 任务栏图标一直闪」，裸模型三步修好；加 skill 的那份先讲「止损 → 取证 → 定位」，结构更好，可是用户只想要图标别闪。

**后来怎么处理的**：两个失分模式都修了——占位符只许占「值」，不许占「整节」；小操作故障不吃交付契约。同一套题重测，变成**打平**——它不再输，但也没开始赢。同时冒出来两种新失分形态（编造不存在的文件路径、绕开安全软件），现在在主干里是硬禁区。

**我们没做的**：v1.6.0 之后**没有重跑**那 9 道题。所以上面所有数字都是 v1.5.x 的测量，不是 v1.6.0 的结论。题目和算式都在 [`bench/`](bench/) 里，欢迎你不同意。

## 那它到底给了你什么

不是更高的分，是**不一样的形状**：

- 你没问的问题，被排成一张带优先级的清单，而不是被默默丢掉；
- 假设被明确标成假设，你可以当场否掉；
- 琐碎请求还是琐碎，闸门会把框架挡在外面；
- 结论自带边界：*这一条在什么条件下成立、换成什么条件就翻*。

如果你要的是「回答质量变高」，别装。如果你要的是「少漏东西，并且知道它替我假定了什么」，这个能做到，而且稳定。

这个承诺比大多数提示词包小，但它是活下来的那个。

## 自己跑一遍

```bash
cd bench
python run.py --list                 # 10 道题，3 个类别
python run.py --emit 01 --arm bare   # 打印要发给模型的提示词
python score.py                      # 填完 scores.md 后算 Δ
```

`bench/` 只给题目、空评分表和 Δ 的算法。**不给答案**——不给你可以盖章的结论。

## 这里没有什么

- 不联网、不埋点、不碰你的 key。纯文本进，纯文本出。
- 没有「25 个技巧让你效率翻十倍」。见上面那节。
- 不防提示词注入。宿主被攻破了，一份文本内核救不了你。
- `demo/` 面板目前中文优先，英文模板在路上（见 [CHANGELOG](CHANGELOG.md)）。

## 归属

25 项思想**不是原创**。费曼学习法、苏格拉底追问、事前验尸、红队、分治、剪枝、记忆化——全部是公开的、早于本仓库存在的。

这里主张的只有三样：**筛选、每项的失效边界、以及装配方式**（闸门 → 场景 → 力度 → 注入）。

发现漏了出处，开个 issue，会补上。
