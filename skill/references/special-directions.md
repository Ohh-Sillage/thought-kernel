# 特殊特化方向库

记录「**单一维度极大强化、其他维度略微牺牲**」的可选方向。

这类方向的共同特征：在某一个指标上做到极端（例如 token 降 3/4），代价是另一个指标小幅下滑（例如掉 1 分）。
它们**不是默认配置**，也**不是失败品**——而是实测过的极端点，留作特定场景的可选路径。

启用规则：

- 默认**不启用**。只有用户明确表达对应偏好时才切换。
- 每条方向必须写明「适用」与「不适用」，不适用时禁止启用，不靠模型自行判断。
- 启用后仍需守住红线项（见每条的「不可压缩项」）。

---

## D1 极限压缩（extreme-compact）

**一句话**：用条目标题式骨架替代展开论述，用 60—75% 的篇幅降幅换取约 1 分的质量损失。

> **注意**：v1.3.2 起 medium 档默认会给细节（见 `difficulty.md` 规则 8），不再掉分。
> 本方向因此成为**用户显式要求更极端压缩时**才启用的选项，不是默认路径。
> 下面记录的 −1.00 是 v1.3.1 时的实测值，用于说明这个方向的代价量级。

### 实测数据

来源：2026-10-26，9 题 / 34 单元，arm5 vs 裸模型，同批匿名盲评 + 独立复评。

| 指标 | 数值 |
|---|---|
| 输出长度 | 降至裸模型的 **0.27x**（medium 题 4558 → 1238 字符） |
| medium 题质量 | 配对差 **−1.00**（三题一致，无一例外） |
| complex 题质量 | 配对差 +0.33 ~ +1.33（反而更好） |
| 总体 | 0.00（不亏不赚，但方差大） |

**关键事实**：这个方向在 complex 题上是**纯赚**（更短且分更高），在 medium 题上是**净亏**（省 73%、掉 1 分）。
所以它不是「全局好」或「全局坏」，而是**分难度反向**。

### 适用（启用理由成立才用）

- 用户明确说「省 token」「快速草稿」「不用太细」「先给个框架」
- 输出只供用户自己看，不进正式交付物（不进邮件、不进汇报、不发给同事）
- 上下文紧张，需要在历史轮次上压缩
- 批量处理：单条价值低、但条数多，总成本敏感

### 不适用（禁止启用）

- **medium 难度的任务**——这是实测掉分最确定的一类。medium 的检查要点要求
  「目标可衡量 / 每阶段可检验产出 / 反馈机制」，这些必须有具体数值与验收标准，
  纯条目标题撑不起来
- 对外交付物：邮件、汇报材料、方案文档、任何要给别人看的产出
- 用户没有显式要求省 token 时（不要自作聪明替用户省）
- **与 `efficiency` 模式混用**——两者不是一回事，见下表

### D1 与 efficiency 模式的区别（不要混用）

| | `efficiency` 模式 | D1 极限压缩 |
|---|---|---|
| 前提 | **不降低准确率** | 接受掉约 1 分 |
| 省多少 | 实测 43—54%（decision/exec 场景，且分数更高） | 73%（medium 场景，且分数更低） |
| 触发 | 用户说「效率优先」「省点 token」「快点说重点」 | 用户说「可以糙一点」「掉点质量没关系」「先给个框架就行」 |
| 关系 | 默认的省成本路径 | 比 efficiency 更极端的档位，需用户明确接受降质 |

**判断顺序**：先说「效率优先」→ 走 `efficiency` 模式（不掉分）；
进一步说「质量可以降」→ 才切 D1。不要因为用户提了 token 就直接跳到 D1。

### 实现要点（做到这五条才是「极限压缩」，否则只是「写得潦草」）

1. **每节留一行结论 + 一个编号列表**，不写「为什么这样做」的理由段
2. **不开二级小节**（`###`），全部压到一级（`##`），减少层级跳转
3. **关键数值内嵌在括号里**，不单独成句：写「W1—W2（6—8 人，不停机）」，
   不写「第一阶段为期两周。假设团队规模为 6 到 8 人，且不允许停机。」
4. **条件出口一行写完**：「若 X 则 A，若 Y 则 B」，不逐条列举四五个分岔
5. **不写导读段**：不说「下面我按四个方面展开」，直接进第一点

### 不可压缩项（即使极限压缩也必须保留）

这三项是被扣分的重灾区，砍掉它们会让 1 分变成 3—4 分：

| 项 | 为什么不能砍 |
|---|---|
| **假设声明** | 检查要点常要求「先澄清或列出假设」。一行写完也行：「假设：A、B、C，不符请替换」 |
| **双向判据** | 检查要点要求「如何验证」。必须留「什么现象说明成立 / 什么现象说明不成立」两条，不能只留一条 |
| **止损红线** | 涉及改动、上线、重构的任务，必须有回滚或熔断。一行也行，但不能没有 |

### 为什么保留这个方向

这是目前唯一实测过的「省 3/4 篇幅只掉 1 分」的极端点。在 token 敏感的批量场景下，
1 分的质量损失可以接受，而 3/4 的成本降幅很有价值。**丢弃它等于丢掉一个已验证的极端点**，
将来遇到大批量、低成本、非交付的生成任务时，没有可参照的实现。

## 方向登记规范（新增方向时遵守）

每条新方向必须包含六项，缺一不可：

1. **一句话定义**：强化了什么、牺牲了什么
2. **实测数据**：至少一个场景的配对差 + 成本变化，标注来源与日期
3. **适用条件**：什么情况下启用是合理的
4. **不适用条件**：什么情况下禁止启用
5. **实现要点**：要怎么做才算「做对了这个方向」，而不是「做得潦草」
6. **证据路径**：能查到原始数据的文件

**禁止**只写「可以更简洁」这类方向性描述——没有实测数据的偏好不是特化方向，是个人口味。
