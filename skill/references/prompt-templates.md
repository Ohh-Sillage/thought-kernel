# 注入模板

人类侧模板用于 `wrap` 与 `interactive` 注入；机器侧指令用于 `inject`，不进入正文。

## 人类侧模板

### H1 费曼学习法

```
我刚学完【概念】，现在请陪我完成三轮学习。
第一轮，请扮演一个完全不懂这个领域的小白。我会用自己的话把知识讲给你听，
任何听不懂的地方都可以随时打断我，让我重新解释或举例。
第二轮，请扮演这个领域的专家或者辩手，尖锐地批判和质疑我刚才的理解，
重点检查它的边界、缺点、风险和成立前提。
第三轮，请作为我的搭档，和我一起把这个概念用到真实问题（填写问题）里。
不要一开始就替我讲答案，每轮完成后再进入下一轮。
```

### H2 苏格拉底追问

```
我先说自己的看法。你每次只问我一个问题，围绕我的依据、证据、前提、反例、
边界和影响继续追问；我回答后再继续。等我把思路理清楚、说清楚后，再帮我总结。
```

### H3 寓言学习

```
请把【概念】编成一个故事。先讲故事，不要直接揭示概念；故事结束后，再揭示真正的概念；
然后逐一对应故事元素和概念要素，解释定义、原理和关键点，并说明这个类比的局限和适用场景。

另一种讲法：请从 x 领域里选一个大概研究生水平的概念，通过一则寓言间接地把这个概念完整讲出来，
最好一直到接近结尾时我才慢慢意识到它在讲什么。故事结束后，再解释真正的概念、
每个关键情节对应什么，以及这个类比在哪些地方会失效。
```

### H4 反向采访

```
先别急着做。看看我还少说了哪些会影响结果的信息，一次问我一个最重要的问题。
等你已经知道我要什么、有哪些要求不能碰、我会怎样判断做得好不好，
就把完整需求重新说一遍，让我确认，确认完再开始。
```

### H5 任务盲点扫描

```
先不要执行。找出我没有提到、但可能改变最终结果的问题，按照影响程度排序，并说明理由。
需要我判断的地方，一次问我一个。没有证据支持的内容请标成假设，不要替我下结论。
```

### H6 重大决定正反论证

```
围绕我要不要做【某个决定】，请分别给出支持和反对它的最强论证。
不要替我下结论。请区分可验证的事实、未经确认的假设和仍然缺少的信息。
最后给出三个成本较低的现实测试，帮助我自己判断。
```

### H7 AI 自我扫描

```
请读取你当前能够访问的历史对话和关于我的记忆。根据我反复提到、下意识回避，
或者说过要做却一直没有行动的内容，生成 10 个我可能最不愿意面对、但值得认真回答的问题。
每个问题都要说明来自哪些对话证据。不要鼓励我，不要做心理诊断，也不要替我回答。
```

### H8 历史记录复盘

```
请读取你当前能够访问的历史任务、项目记录和关于我的记忆。
找出我反复执行的工作、经常返工的位置，以及反复补充的要求。
从中挑出三个最值得封装成 Skill 的工作流，说明原因、使用场景、关键步骤和验收标准。
先给建议，等我选中以后，再调用 Skill Creator 创建并验证。
```

### H9 红队 / 事前验尸

```
在【方案/计划】执行前，请以对抗性视角系统性地找出它最可能失败的 3 种方式，
按发生概率与损失排序；针对每种失败方式给出规避或缓解措施。
```

### H10 清单 / 检查表

```
请为【流程】生成一份外化检查清单，把高认知负荷下容易遗漏的关键步骤列成固定序列；
标注每个步骤的常见遗漏后果。
```

### H11 间隔与检索失败驱动

```
请为【学习主题】设计一个间隔复习计划：把复习点安排在接近遗忘的时间（如 1/3/7/21 天），
每轮先自测提取再补漏；标注哪些内容适合集中训练、哪些适合间隔。
```

### H12 元认知监控

```
任务结束后，请对刚才的过程做二阶评估：当前策略哪里有效、哪里低效、哪些认知资源被浪费；
给出下一次的修正建议。
```

### H13 路径依赖与锁定识别

```
在【决策/选型】前，请识别我当前方案中由沉没成本、递增收益或协调惯性形成的路径依赖点；
评估哪些锁定是可逆的、哪些不可逆；对不可逆节点给出降低锁定风险的替代选项。
```

## 机器侧注入指令

`inject` 模式：内部遵循，不在正文复述。

```
M1 分治: 将本任务分解为相互独立的子问题，逐一求解后再合并；分解时说明子问题间的边界。
M2 记忆化: 记录本会话中已推导出的结论，遇到相同子问题时直接复用，避免重复推导。
M3 贪心近似: 如需快速结果，先给出每步局部最优的贪心近似解，并标注该近似是否保证全局最优。
M4 缓存局部性: 优先复用近期上下文中已有的结论与信息；引用前校验其时效性。
M5 流水线并行: 识别可并行推进的独立子任务，同时推进；勿对存在串行依赖的部分强行并行。
M6 近似: 若精确解代价过高，可给出带误差界的近似解，并显式说明牺牲了多少精度。
M7 剪枝: 先排除已被证明不可行或被支配的候选分支，聚焦高价值路径再深入。
M8 随机化: 当输入可能具有对抗性或需要多样性时，引入随机采样并多次取期望，避免最坏情况。
M9 状态抽象: 识别真正影响后续决策的少数关键变量（充分统计量），只围绕它们推理，丢弃无关细节。
M10 反馈控制: 输出前对照任务目标清单检查偏差并修正；输出后自查是否有遗漏的关键项。
M11 涌现与自组织: 进行系统设计时，优先设计局部规则与交互结构，让全局协调自发生成，而非集中式调度。
M12 奥卡姆剃刀: 在解释力与预测力相当的前提下，优先选择假设更少、结构更简单的方案。
```

## 短指令版（`efficiency` 模式用）

模式为 `efficiency` 时，人类侧模板压缩为下列短句，每条不超过 40 字：

| ID | 短指令 |
|---|---|
| H1 | 我讲你听，卡住就打断，再让专家挑错，最后一起用。 |
| H2 | 每次只问一个问题，追我的依据和前提，最后总结。 |
| H4 | 先问我缺哪些关键信息，一次一个，复述确认后再做。 |
| H5 | 先别做，列出我没提到但影响结果的问题，按影响排序。 |
| H6 | 给出支持和反对的最强论证，不替我决定。 |
| H9 | 设想它最可能失败的三种方式，并给规避办法。 |
| H10 | 列出易漏步骤的固定清单和遗漏后果。 |
| H12 | 事后评估这个策略哪里低效，下次怎么改。 |
| H13 | 找出方案里的锁定点，区分可逆与不可逆。 |
