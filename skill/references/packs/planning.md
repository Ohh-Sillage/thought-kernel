# 场景包：制定计划（`planning`）

## 1. id 与语义标签

`planning` —— 从零到可执行：把一件还没开始的事排成有阶段、有验收、有时间的方案。

## 2. 适用信号

用户要的产物是**一份能照着推进的安排**：

- 「帮我规划 / 设计 / 排个计划 / 怎么推进 / 从哪开始」；
- 给了一个目标或约束（预算、期限、团队规模），等的是路径而不是代码；
- 问「这个方案行不行」「还有没有更好的做法」，且下一步要拿去做决定或开工。

判据：**产物是不是一张「什么时候做什么、怎么算做到了」的表**。是 → 本场景。

## 3. 不适用信号

| 易混场景 | 凭什么排除它不属于本场景 |
|---|---|
| `coding` | 用户要的是**能跑的东西**（代码、脚本、接口），不是安排。有「实现 / 写个 / 开发」且要可运行 → 走 `coding` |
| `decision` | 卡在**选哪一个**（A 还是 B、要不要做），还没有进入「怎么做」。判据：他连方向都没定 → `decision` |
| `research` | 要的是**有哪些选项 + 各自事实 + 证据强弱**，不是执行路径 |
| `exec`（兜底） | 只要一条建议、一个判断或一段解释，不需要阶段与验收 |
| `review` | 对象是**已经发生的事**（做完了复盘），不是还没做的事 |

**边界提醒**：「帮我设计一个 X」是这两个场景的经典歧义——**要图纸还是要不要开工**。
要拿去开工（有时间、有验收）→ 本场景；只是想知道「这东西该怎么设计」（架构、模块划分）→ 也给本场景，
但交付形态是设计说明而非排期表，见字段 4。

## 4. 默认交付形态

**一份带验收与时间的推进表**：阶段划分 → 每阶段做什么 → **怎么算做完（可核对）** → 什么时候做完。
不是「思路」「几个方向」「注意事项」。

若用户问的是「该怎么设计」而非「怎么推进」，形态换成**设计说明**：对象 / 边界 / 关键取舍 / 什么情况下会推翻它——
但仍要有可核对的判据，不能停在架构图。

## 5. 注入内容

**沿用通用三档装配，本包不额外覆盖注入额度。**（人类侧与机器侧条数以 `@references/modes.md`
与 `@references/difficulty.md` 为准。）

但有一条**不可被裁的必需项**：

> **需求澄清（`H4` 反向采访 / 需求复述）在中等及以上难度不得被裁掉。**
> 理由：本场景最大的失分来源是「按自己的假设排了一套计划」，而用户真正的约束（期限、人手、已有资产）
> 一条都没问。裁掉澄清省下的 token，换来的是一份要重做的计划。

## 6. 硬约束

1. **必须落到可核对的实体**：阶段要有**具体数值、验收标准、时间窗**。
   - 不合格：「加强测试」「持续优化」「尽快上线」
   - 合格：「第 4 周能不看稿讲满 3 分钟，卡顿 ≤3 次」——有动作、有判据、有时间
   实测依据：把 medium 题压到只列条目标题时，`planning` 靠「给数值」才修好（+1.00）。
2. **覆盖到「能动手的那一层」，不停在架构描述**。
   实测（T26 h001）：一份只讲到「端点 + 定时任务」的方案，被两位评委判「架构取舍缺失」——
   因为它没说清数据怎么存、失败了怎么办、先做哪一块。
   **判据：读者按这份计划能不能排出明天的第一件事。**
3. **前提显式化**：用户没给但会改变结论的约束（期限、预算、人手、已有系统）必须标出来或反问一句，
   不得直接假设成既定事实来排期。
4. **给出「不做什么」**：至少一条被明确排除的路径及理由。计划的价值一半在取舍，不在罗列。

## 7. 失效边界

- **不要用「先做准备工作」开头**。T26 实测：把「先讲止损 / 先做需求梳理 / 先建评估集」放在第一段的版本，
  比直接给方案的版本低 1.5 分。准备工作要放在方案之后，作为「开工前确认」。
- **不要给整齐的八阶段甘特图**。阶段数超过 5 个且每阶段都「调研→设计→开发→测试」的，是模板不是计划。
- 用户只问「这个想法行不行」时，本场景的交付物会变成一份他不要的排期表——这是 `decision` 的题（见字段 3）。
- 已有一份计划、用户要的是「看看漏了什么」时，交付形态是**补漏清单**，不是重排一遍。

## 8. 自检项

- 每个阶段都有可核对的验收标准（数值 / 现象 / 产出物），没有「加强」「优化」「推进」这类空动作。
- 有时间窗，且时间窗与阶段工作量匹配（不是全都「1 周」）。
- 读者能据此排出明天的第一件事。
- 至少一条被排除的路径与理由。
- 影响结论的前提已标出或反问，没有静默假设。
- 没有把「准备工作」放在第一段。
