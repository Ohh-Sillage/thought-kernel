# 三种提示词模式

## 目录

三种模式共用同一套思想库，只在「附加多少、说多细、查多严」上分档。模式不改变思想的注入方式（`wrap` / `interactive` / `inject`），只改变条数、模板长度、场景识别范围与自检强度。

## 模式定义

### 效率优先（`efficiency`）

- 目标：在不降低准确率的前提下，尽量提高效率、减少 token 消耗与交互轮次。
- 适用场景：简单查询、重复性任务、上下文窗口紧张、快速草稿与探索、结果错误可承受且易修正。
- 不适用：不可逆决策、对外交付物、事实核查、金额与合规相关判断。

取舍规则：

1. 机器侧思想取 1—2 条，默认 `M7 剪枝 + M9 状态抽象`；同一任务不叠加同类思想。
2. 人类侧自动建议最多 1 条；`interactive` 思想不自动建议，仅在用户显式点名时启用。
3. 场景识别只取置信度最高的 1 个场景。
4. 模板压缩为短指令：每条不超过 40 字，只保留动作要求，不复述原理与边界。
5. 不弹建议卡片，也不输出标注行：直接按思想作答，用户可随时叫停或追问附加了什么。
6. 输出结构：直接给答案，不展开推理过程、不复述问题、不重复解释已出现的术语。
7. 假设标注只覆盖会改变结论的关键假设。
8. 输出前自检一次，不做事后二次核验。

不可降级的底线（保证「不降低准确率」）：

- 事实性、计算性结论必须自检一次，无法确认时标注「未验证」。
- 不得为省 token 省略不确定性说明或风险提示。
- 高风险领域（医疗、法律、金额）自动升档到 `accuracy` 的假设标注要求。

### 准确度优先（`accuracy`）

- 目标：在不显著降低效率的前提下，尽量提高准确度、可验证性与边界完整性。
- 适用场景：决策与选型、代码实现与审查、事实核查、对外交付物、长期维护的方案、高风险领域。
- 不适用：上下文极紧张、用户明确要一句话结论、纯格式转换。

取舍规则：

1. 机器侧思想取 3—4 条，必须包含 `M10 反馈控制`；要求显式分步推理与输出前对照目标检查。
2. 人类侧完整建议，最多 4 条；`interactive` 思想默认建议启用，仍需用户一行确认。
3. 场景识别取 top-2，两个场景的思想取并集后去重。
4. 模板使用完整版，保留原理一句、边界与反例说明。
5. 关键结论至少两条独立证据链；只有单一来源时标注「单一来源」。
6. 输出结构：结论前置 → 证据或来源 → 反例与反方观点 → 边界条件 → 三类假设标注。
7. 允许 `M8 随机化` 做多角度自检：换一种思路重算关键结论，不一致时说明分歧。
8. 输出前、输出后各检查一次；输出后检查遗漏与自相矛盾。

效率护栏（保证「不显著降低效率」）：

- 禁止无界穷举与全量枚举。
- 子任务拆分深度不超过 3 层；超过时先合并再继续。
- 已验证的结论不重复验证；同一论据不重复引用。
- 正文不超过任务所需；不为了「显得严谨」堆砌免责声明。

### 均衡（`balanced`，默认）

- 目标：同时兼顾效率与准确度，按任务复杂度动态分配。
- 适用场景：日常工作的默认档；中等复杂度、后果可控的任务。

取舍规则：

1. 机器侧思想取 2—3 条，采用场景映射表的默认组合。
2. 人类侧建议最多 3 条；`interactive` 思想需用户确认后启用。
3. 场景识别取 top-2，但人类侧只取置信度最高场景的默认集。
4. 模板使用标准版：动作要求加一句边界说明。
5. 输出结构：结论加简要依据，不展开完整推理链。
6. 关键结论至少一条证据；涉及数字与事实时补第二条。
7. 假设标注覆盖关键假设。
8. 输出前自检一次。

## 量化对照

| 维度 | `efficiency` | `balanced` | `accuracy` |
|---|---|---|---|
| 机器侧思想条数 | 1—2 | 2—3 | 3—4 |
| 人类侧建议条数 | 最多 1 | 最多 3 | 最多 4 |
| 场景识别范围 | top-1 | top-2 | top-2 |
| 模板长度 | 短指令（≤40 字） | 标准（动作+边界） | 完整（原理+边界+反例） |
| 建议卡片 | 关闭，不输出标注 | 开启 | 开启 |
| 假设标注 | 关键项 | 关键项 | 三类全标 |
| 输出自检 | 1 次（前） | 1 次（前） | 2 次（前+后） |
| 证据链要求 | 不强制 | 关键结论 1 条 | 关键结论 2 条 |
| 多角度自检（M8） | 不用 | 可选 | 关键结论执行 |
| 相对 token 消耗 | 基准的 40—50% | 基准的 60—70% | 基准（100%） |

「基准」指同一任务在 `accuracy` 下的典型消耗。

## 切换方式

| 方式 | 说法示例 | 生效范围 |
|---|---|---|
| 消息内显式指令 | 「这次效率优先，直接给结论」「准确度优先，把依据列出来」 | 仅本条请求 |
| 会话内切换 | 「以后都用效率优先」「切到准确度优先」「恢复默认模式」 | 当前会话，直到再次切换 |
| 显式语法 | `/thought-kernel mode efficiency`、`/thought-kernel mode accuracy`、`/thought-kernel mode balanced` | 按会话规则 |
| 配置默认值 | 插件或面板的默认模式设置 | 跨会话，用户未指定时生效 |

优先级：消息内显式指令 > 会话内切换 > 配置默认值 > `balanced`。

## 冲突与边界处理

1. 用户显式点名的思想优先于模式裁剪：用户选了 3 条人类侧思想时，`efficiency` 也不裁掉。
2. 模式只作用于自动附加部分；用户点名部分原样保留。
3. 前置闸门判 `skip`（零落差）时，不进入场景判定，直接作答：不加框架，也不做以任务目标为对象的自检。场景认不出但确有任务（权重和 <2 且无语义归属）时，先按 `inherit` 退回上文；上文也读不出，才走 `exec` **兜底**：按 `SKILL.md`「兜底」一节的三条通用交付下限作答（完整度不降级 / 前提显式化 / 结尾一句边界），并保留 `M10` 自检一次。**闸门判 `lite` 时一律不进兜底**，直接作答。**`skip` 与兜底不是一回事**——前者是对「没有值得做的事」的处理，后者是对「有任务但认不出场景」的处理；前者可以短，后者不可以。
4. 前置闸门判 `lite` 时只注入 1 条：情绪是主诉则「接住处境 + 一个下一步」，任务是小落差则「一条能立刻改变结论的补充」。`lite` 下不启用 `interactive`，也不启用 `H9`。判不准**有没有落差**时落 `lite`，不落 `skip`。
5. 同一请求里出现互相矛盾的模式指令（如同时说「快点」和「严谨点」）：按后出现的为准，并一行说明。
6. 高风险任务自动升档：`efficiency` 下遇到医疗、法律、金额判断，假设标注与证据要求升到 `accuracy` 水平，其余保持高效。
7. 用户手动降档但任务不可逆：给出一行风险提示，不强行阻止。
